# 07. 맥 메뉴 막대 앱 (빠른 추가)

## 목표
사이트를 열지 않고, 어느 앱에서든 단축키 → 한 줄 입력 → 비서가 알아서 처리.

## 구성
| 부분 | 내용 |
|---|---|
| `mac/QuickTodo/main.swift` | Swift 한 파일(AppKit). 외부 라이브러리 없음, `swiftc`로 빌드 |
| 단축키 | Carbon `RegisterEventHotKey`로 `⌘⇧D`. 손쉬운 사용 권한이 필요 없다 |
| 입력창 | 테두리 없는 `NSPanel` + `NSVisualEffectView`(반투명), 640x56, 마우스가 있는 화면 위쪽 1/3 |
| 전송 | Enter → 창은 바로 닫고 `POST /chat` → 결과를 맥 알림으로(처리한 일 + 비서 답) |
| 메뉴 막대 | 밀린 일·오늘 할 일(누르면 완료), 빠른 추가, 웹 화면 열기, 종료. 처리 중에는 아이콘이 바뀜 |
| 자동 실행 | LaunchAgent 두 개: 백엔드(항상 유지), 메뉴 막대 앱(직접 종료하면 다시 안 켬) |
| 웹 화면 | `WEB_DIST`를 주면 FastAPI가 빌드된 프론트를 `/`에서 내려 줌 → Vite 없이 8000 하나로 |

`⌘+A+D`는 쓰지 않았다. 글자 키 두 개 조합은 전역 단축키로 등록할 수 없고, 흉내 내려면 모든 앱의 `⌘A`(전체 선택)를 가로채야 한다.

## 겪은 문제
| 문제 | 원인 | 해결 |
|---|---|---|
| 백엔드 LaunchAgent가 `can't open input file`로 종료(127) | 로그인 시 실행되는 프로그램은 macOS 개인정보 보호(TCC) 때문에 `문서` 폴더를 읽지 못함 | `install.sh`가 백엔드·웹 빌드·compose 파일을 `~/Library/Application Support/ai-todo`로 복사하고 거기에 가상환경을 따로 만들어 실행 |
| 사본 위치에서 `docker compose`를 돌리면 새 DB가 생김 | compose 프로젝트 이름이 폴더 이름에서 나옴 | `-p ai-todo-assistant`로 고정해 기존 컨테이너·데이터 사용 |
| 재설치 때 `Bootstrap failed: 5` | `launchctl bootout`이 비동기라 내려가기 전에 다시 등록 | 서비스가 사라질 때까지 기다린 뒤 등록 |
| 실행용 가상환경이 Python 3.9로 만들어질 뻔함 | 맥 기본 `python3`가 3.9 | 개발용 가상환경의 원본 파이썬 경로로 생성 |
| 한글 입력 중 Enter가 조합 확정이 아니라 전송이 됨 | 조합 중에도 `insertNewline`이 옴 | `hasMarkedText()`면 전송하지 않음 |

## 확인
- `install.sh` 두 번 연속 실행 → 두 서비스 모두 실행 중, `/health` 정상, `/`에서 웹 화면
- 로그에 `단축키 ⌘⇧D 등록됨`
- 창 목록으로 메뉴 막대 아이콘과 입력창(640x56) 표시 확인
- pytest 37개 통과 (`WEB_DIST` 테스트 추가)
- 화면을 직접 조작해 확인: 입력창 표시, 한글 입력, Enter 전송 → "내일 오후 3시 치과 예약 추가해줘"가 11/17 15:00으로 추가, 메뉴 막대 메뉴, Esc 닫기
- `⌘⇧D`는 자동화 도구의 키 입력으로는 전달되지 않아 사용자가 직접 눌러 확인
- 확인하지 못한 것: 결과 알림 배너 (테스트 때 집중 모드가 켜져 있었음)

## 추가: 할 일 창 (브라우저 없이)
- 같은 앱에 `WKWebView` 창을 붙여 웹 화면을 그대로 보여 준다. 화면을 두 벌 만들지 않기 위해서다
- 창이 열려 있는 동안만 Dock·⌘Tab에 보이고(`.regular`), 닫으면 다시 메뉴 막대만(`.accessory`)
- Launchpad·Spotlight로 앱을 다시 열면 새로 뜨지 않고 `applicationShouldHandleReopen`에서 창을 띄운다
- `⌘Q`는 창만 닫는다. 앱이 꺼지면 단축키도 죽기 때문
- 메인 메뉴(편집)를 추가: 이게 없으면 입력창과 창 안에서 `⌘C/⌘V`가 안 된다
- 빠른 추가·메뉴 막대에서 바꾼 내용은 `todos-changed` 이벤트로 열린 창에 바로 반영, 웹 쪽은 창 포커스 때도 새로 고침
- 입력창을 닫을 때 `NSApp.hide`가 할 일 창까지 숨기던 문제: 창이 떠 있으면 숨기지 않게
- 확인: 앱 열기 → 인스턴스 1개 유지, 1320x840 창 생성, 창 안에서 `/`·`/todos`·`/chat`·`/health` 요청. 창의 겉모습(신호등 버튼 자리)은 눈으로 확인하지 못함

## 추가: 다시 설치해도 옛 화면이 뜨던 문제
- 증상: 날짜 선택 UI를 바꾸고 재설치했는데 앱 창에는 예전 화면이 그대로
- 원인: PWA 서비스 워커가 WKWebView 안에도 등록돼, 캐시에 있던 옛 화면을 먼저 보여 주고 새 파일은 뒤에서만 받음. 서버 기록에 창이 `/`가 아니라 `sw.js`·`workbox`만 요청한 것으로 확인
- 수정
  - 로컬 설치용 빌드(`LOCAL_APP=1`)는 `selfDestroying`으로 서비스 워커를 끄고 이미 등록된 것도 지움. 배포본(PWA)은 그대로
  - 앱 창은 저장소를 남기지 않고(`nonPersistent`) 캐시를 무시하고 로드
  - 백엔드가 `index.html`에 `Cache-Control: no-cache` (해시가 붙은 `assets/`는 제외), 테스트 추가
- 확인: 재설치 후 창을 열면 서버에 `GET /`와 최신 해시의 js·css 요청이 찍힘
